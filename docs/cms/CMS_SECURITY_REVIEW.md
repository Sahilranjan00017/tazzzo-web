# CMS security review

Scope: `apps/admin` as of branch `cms/16-qa-security` (stack head). Method: source greps, policy tests, unit/integration/E2E tests
against a mock OIDC provider and mock backend. NOT done: external penetration test, dependency audit run locally (pnpm is
unusable on the review machine; the CI "Dependency audit (production, high+)" job is the evidence and was green on every PR
checked), review against a real backend or real Google Workspace.

## Findings fixed during this program

1. PR #4 hardening: inline style in `global-error` (CSP), focusable hidden drawer, mixed ARIA menu semantics.
2. Dashboard linked stock counts to a lookup page and order counts to a page the dashboard's own audience cannot open: links are now role-aware and only to real list pages.
3. Imports menu entry was visible to `reader` although imports are `cms-writer`-only (found by the matrix test).
4. Actions could be clicked on a stale version during the post-save refresh (found by E2E): all actions now disable while a refresh is pending.
5. A file chosen before hydration was silently dropped (media, imports): inputs now adopt a pre-existing selection.
6. 360 px horizontal overflow (grid min-width, file inputs) found by the responsive sweep and fixed.
