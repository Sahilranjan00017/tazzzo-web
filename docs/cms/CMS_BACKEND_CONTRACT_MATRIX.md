# CMS backend contract matrix (admin / staff-facing HTTP surface)

**Backend:** `tazzzo-backend-main`, `origin/main` @ `c3306b6` ("Retention doc: drop the two stale ... (#90)").
**Method:** read-only. Source was exported with `git archive origin/main` into a scratch directory; the working copy was never touched. Every claim below was read from controller/service code on that commit. `UNKNOWN` = not determinable from the repo.
**Citation root:** `J/` = `services/catalog-service/src/main/java/com/tazzzo/`. `docs/...` paths are repo-root-relative in the backend.
**Generated spec:** `services/catalog-service/docs/openapi.json` (73 `/api/**` operations, 62 `/api/**` paths, 32 under `/api/v1/admin`) lists every endpoint in this file. `docs/api/v1/openapi.yaml` is the **customer/public `/v1/**` contract only** (`openapi.yaml:3-6`); it contains **no** admin endpoint.

---

## 0. Bottom line for the CMS integration

1. All admin endpoints live under `/api/**` (surface `INTERNAL`, `J/catalog/api/SurfaceClassifier.java:88-89`). Auth = `Authorization: Bearer <token>` only. Use a server-side BFF (CORS is off by default).
2. There are exactly **five role strings**: `reader`, `cms-writer`, `audit-reader`, `order-ops`, `support-agent` (`J/admin/auth/AdminPrincipal.java:30-36`; allowlist rejects any other name at startup, `J/admin/auth/HumanAdminSettings.java:31-32,104-105`). Plus two **shared service-token identities** (`service:reader`, `service:cms-writer`), which are principals, not roles.
3. **The shared service tokens can never reach `/api/v1/admin/orders/**` or `/api/v1/admin/support/**`** (`AdminAccessPolicy.java:56-58`). The BFF must forward each signed-in staff member's own **Google OIDC ID token** (per-person, `HUMAN_ADMIN`) for orders and support. ID tokens expire; expect 401 `UNAUTHENTICATED` and refresh.
4. Concurrency is **three different styles**: `If-Match: <bare int>` (products only), `expectedVersion` in the JSON body (everything else), and none (classify / claim-publish / bind-GTIN / merge / support reply). There is **no ETag and no `Idempotency-Key` on any admin endpoint**.
5. No list endpoints exist for prices, stock, releases, evidence, attributes, brands, notifications, or customers.

Pipeline: `RequestIdFilter` -> `RequestBodyLimitFilter` -> CORS -> `ApiAuthFilter` (`J/catalog/api/ApiAuthFilter.java:42`). Decision is made in ONE place, `AdminAccessPolicy.decide` (`J/admin/auth/AdminAccessPolicy.java:30-52`).

Predicates (`AdminPrincipal.java:61-77`): write = has `cms-writer`; catalogue read = `reader` or `cms-writer`; staff = HUMAN_ADMIN holding `order-ops` or `support-agent`; audit read = HUMAN_ADMIN holding `audit-reader`.

### 1.2 Rules (`AdminAccessPolicy.java:30-66`)

- "Read" means **GET only**. Every other method (incl. HEAD) is a write (`:31`).
- Raw URI containing `;` or `%` -> 403 (`:34-36`); `SurfaceClassifier` already rejects `;`, `%`, `\`, `.`/`..` segments as UNKNOWN -> 404 `NO_SUCH_ENDPOINT` (`SurfaceClassifier.java:125-138`, `ApiAuthFilter.java:91-94`). **Every path id must be usable un-percent-encoded.**
- `/api/v1/admin/orders[/**]`: `order-ops` R+W, `support-agent` R only; HUMAN_ADMIN only. `/api/v1/admin/support[/**]`: `support-agent` R+W, `order-ops` R only; HUMAN_ADMIN only. Nothing else reaches these (not `cms-writer`, `reader`, `audit-reader`, no shared token) (`:37-41,55-66`).
- Everywhere else: write needs `cms-writer`; read needs `reader` or `cms-writer`; a principal with neither may GET only the "narrow" paths: `/api/v1/admin/me` and `/api/v1/admin/audit-events` (`ApiAuthFilter.java:46-50`); for a **staff** principal the narrow set shrinks to `/api/v1/admin/me` only (`:50,114-115`).
- Refusals: 401 `UNAUTHENTICATED` "missing or unknown bearer token" (missing/invalid/expired/domain-mismatch/unverified-email); 403 `FORBIDDEN` "admin access not granted" (not allowlisted / disabled); 403 `FORBIDDEN` "role may not perform writes here" / "role may not read this resource" (`ApiAuthFilter.java:109,120-123,136-153`).

### 5.1 Additional integration findings (gap 11)

1. **Shared tokens cannot serve orders/support** - the BFF needs per-user Google OIDC ID tokens; tokens expire; allowlist keyed by provider+subject; hosted-domain enforced (`AdminAccessPolicy.java:56-58`; `HumanAdminSettings.java:58-76`).
2. **Product list cannot filter `lifecycle` or classification `status` without `verticalId`** (400) - no "all drafts" queue (`ProductController.java:86-88`). No product text search, no brand filter, no total count; list rows carry no price/stock/media.
3. **Product edit is title-only** (`ProductUpdateService.java:34-55`); no attribute/brand edit; `classify` and `gtins` do not validate vertical/release/GTIN format and `gtins` silently re-assigns a GTIN from another product.
4. **Product ids are client-chosen** (`^TZP-`); cart needs `^TZP-[0-9]{1,18}$` - use numeric ids.
5. **Inconsistent concurrency and pagination styles** (section 2) - one typed client per family.
6. **Stale-version responses never return the current version**; always re-GET.
7. **Empty body = 400 `MALFORMED_REQUEST`, not 422** (the controllers' `body == null` branches are unreachable).
8. **Mixed envelopes**: staff orders/support messages are always generic, codes are raw reason names (`ORDER_NOT_FOUND`, `UNAVAILABLE`, `INTEGRITY_FAILURE`); content passes domain messages; other admin controllers use `NOT_FOUND`, `INVALID_*`; 503 spelled `UNAVAILABLE` (orders/support) vs `SERVICE_UNAVAILABLE` (dashboard) vs 500 `INTERNAL` (content Mongo outage). No `Retry-After` on any admin response.
9. **No location registry**; inventory accepts any well-formed `locationId` (typos create orphan rows, no delete) (`InventoryKey.java:16-25`).
10. **Delivery windows**: unknown `serviceAreaId` list -> 200 empty (not 404); no capacity-usage read; zone/horizon not exposed (`DeliverySlotAdminController.java:43-46`).
11. **Audit is thin**: no before/after `detail`; `targetId` grammar excludes `|` so delivery-window events (`<area>|<window>`) cannot be filtered by id; inventory events carry no location; only attributed events appear.
12. **No admin rate limiting** and **no admin Idempotency-Key**; retries rely on CAS/duplicate conflicts.
13. **Staff PII**: order detail exposes `recipientPhone` and lat/lng to staff (`StaffOrderController.java:70`/`OrderAddressSnapshot.java:19-21`); `customerId` is the only customer identity on support cases.
14. **Content has no "scheduled/expired" status** and published-block edits go live immediately; FAQ authoring must send `placement:"HELP"` (default is HOME) (`ContentAdminController.java:68,81`).
15. **Bulk import**: inventory import path is `/imports/inventory`; dry run skips CAS; per-row `code` is derived from exception class names (`BulkImportService.java:265-269`).
